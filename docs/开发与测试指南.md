# 开发与测试指南

构建、检查、测试、冒烟的完整命令。所有命令在仓库根目录或文中注明的目录下执行。

## 环境要求

| 组件 | 版本 | 用途 |
|---|---|---|
| Go | 1.27 及以上 | 后端编译与测试 |
| Node | 22.12 及以上 | 前端构建与测试 |
| pnpm | 10 及以上 | 前端包管理 |
| PostgreSQL | 18，需要一个可建库的账号 | 运行与集成测试 |
| sqlc | 1.31（仅在改动 `db/query` 后需要） | 生成查询代码 |
| Playwright | 随前端依赖安装 | 端到端测试 |

端到端测试需要四个浏览器：Chrome 与 Edge 用本机安装的稳定版，Firefox 与 WebKit（Safari 引擎）由 Playwright 提供：

```sh
cd frontend
npx playwright install firefox webkit
```

## 初始化

```sh
# 后端
cd backend
cp .env.example .env.local          # 至少填写 JWT_SECRET
psql -U postgres -c 'CREATE DATABASE prompt_benchmark'

# 前端
cd frontend
pnpm install
```

## 本地运行

```sh
# 后端（迁移随启动幂等应用）
cd backend && go run ./cmd/server -env-file .env.local

# 前端开发服务器，/api 反向代理到后端 8080
cd frontend && pnpm dev
```

接口文档：`http://127.0.0.1:8080/api/v1/docs`；OpenAPI 3.1 规范：`/api/v1/openapi.json`；健康检查：`/api/v1/health`；指标：`/api/v1/metrics`（仅回环地址可达）。

## 一键打包与后台运行

开发期前端由 Vite 服务；打包后前端产物内嵌进后端二进制，一个进程提供全部服务：

```sh
deploy/pb.sh build                        # 前端构建 + 内嵌 + 编译，产物 dist/prompt-benchmark
cp backend/.env.example deploy/pb.env     # 首次：填入本机数据库口令等（已 gitignore）
deploy/pb.sh start                        # 后台启动，健康检查通过才返回
deploy/pb.sh status                       # 运行状态与健康检查
deploy/pb.sh logs                         # 最近 50 行日志
deploy/pb.sh stop                         # 停止（SIGTERM，10 秒超时强制终止）
```

启动后页面与接口同源：`http://127.0.0.1:8080`。子命令说明见 `docs/部署手册.md` §五。

本地接收验证码邮件：另开一个进程运行内置 SMTP 接收器，邮件落盘后直接查看：

```sh
cd backend && go run ./cmd/smtpsink -addr 127.0.0.1:2525 -dir .maildrop
```

## 测试

三层测试的构成与覆盖对象见开发方案 §7.1。命令：

```sh
# 后端全部测试（集成测试需要真实 PostgreSQL，用例各自建库并销毁）
cd backend
TEST_DATABASE_URL='postgres://postgres@127.0.0.1:5432/postgres?sslmode=disable' go test ./...

# 只跑某个包或某个用例
TEST_DATABASE_URL='...' go test ./internal/service/stats/ -run '算例' -v

# 前端单元测试
cd frontend && pnpm test

# 端到端测试：脚本先重建 e2e 数据库并清空邮件目录，
# 再由 Playwright 拉起 SMTP 接收器、models.dev 替身、后端与前端预览服务
cd frontend && pnpm e2e

# 只跑 Chrome（默认集）；指定其他浏览器用 --project
pnpm e2e:only --project=firefox
pnpm e2e:only --project=webkit
pnpm e2e:only e2e/smoke.spec.ts --project=edge
```

四个浏览器的全量回归（G-06）：

```sh
cd frontend
pnpm e2e:only --project=chrome --project=edge --project=firefox --project=webkit
```

## 统一门禁

`make gate` 依次执行后端格式、编译、静态检查、测试与前端检查、类型、单元测试、构建、端到端测试。

```sh
TEST_DATABASE_URL='postgres://postgres@127.0.0.1:5432/postgres?sslmode=disable' make gate
```

后端与前端可分别执行 `make backend-gate`、`make frontend-gate`。

## 数据库改动流程

改动 `migrations/` 或 `db/query/*.sql` 后：

```sh
cd backend && make generate   # 重新生成 db/schema.sql 与 sqlc 查询代码
```

规则：

- 正向迁移按编号递增命名，每个迁移都要在 `migrations/down/` 提供同名逆向脚本。
- 已发布的迁移文件不可修改：runner 校验 sha256，改动会使启动直接失败。
- sqlc 无法推导的聚合一律包 `COALESCE`（开发方案 §6.4 的 COALESCE 纪律），避免扫到 NULL 使接口 500。

## 压测

内置压测工具（不进流水线）：

```sh
cd backend
go build -o bin/loadtest.exe ./cmd/loadtest

# 列表接口
./bin/loadtest.exe -url 'http://127.0.0.1:8090/api/v1/prompts?page=1&page_size=20' -c 50 -n 3000
```

千级数据（1000 条提示词、333 条评分）下的实测：列表接口 P95 43.6 ms（目标 ≤ 300 ms）、详情接口 P95 14.4 ms（目标 ≤ 500 ms）、统计接口 P95 8.3 ms（目标 ≤ 200 ms），50 并发错误率 0.000%。压测环境为开发机上的本机 PostgreSQL 实例，不构成对生产硬件的容量承诺。压测时需放宽限流：设置环境变量 `RATE_LIMIT=100000` 启动服务。
