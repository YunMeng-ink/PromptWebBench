## 二、性能指标（技术可行性报告 §3.1）

压测环境：2 核 4G 等效开发机，PostgreSQL 18 本机实例，1000 条公开提示词、333 条评分；50 并发、3000 请求；压测期间放宽限流（`RATE_LIMIT=100000`），使指标反映业务处理能力而非限流拦截。

| 指标 | 目标 | 实测 | 结论 |
|---|---|---|---|
| 列表接口 P95 | ≤ 300 ms | 43.6 ms（`/prompts?page=1&page_size=20`） | 达标 |
| 列表接口区分度排序 P95 | ≤ 300 ms | 30.3 ms（`/prompts?sort=discrimination`） | 达标 |
| 详情接口 P95 | ≤ 500 ms | 14.4 ms（`/prompts/3`，含统计缓存未命中时的重算） | 达标 |
| 统计接口 P95（含 Bootstrap 500 次） | ≤ 200 ms | 8.3 ms（`/prompts/3/stats`，20 并发） | 达标 |
| 并发目标 | 50 并发下错误率 < 0.1% | 错误率 0.000%（三组各 3000 请求） | 达标 |
| 统计缓存 | TTL 可配置、容量上限 10000 条 | 配置项 `stats_cache_ttl_seconds`（默认 60 秒）；容量上限 10000，达上限随机淘汰 | 达标 |

Bootstrap 纯计算耗时由 `TestBootstrap五百次耗时在预算内` 单独守底（4 模型 × 50 样本，500 次重抽样）。

## 五、四浏览器回归中发现并修复的问题

首次四浏览器全量回归 232 项中 228 项通过、4 项失败。逐项核对后确认失败均为端到端用例自身的等待机制缺陷，产品行为正确，已修复用例：

| 用例 | 浏览器 | 根因 | 修复 |
|---|---|---|---|
| 题库协作越权回归 | chrome、edge | `purgeLibrary` 在题库列表异步加载完成前就检查题库是否存在，把「仍在的题库」当成「已删除」而跳过删除步骤 | 等待列表或空态渲染完成后再判断，并在删除后等待回到列表页 |
| 游客查看公开收藏夹 | firefox | 第二次创建收藏夹后断言文案「已收藏」，而该文案本来就在屏幕上，断言立刻通过；随后的导航把尚未完成的创建请求取消 | 改为等待对话框关闭，该信号只在两个请求都成功后出现 |
| 模型导入重复处理 | webkit | 第一次导入的提示气泡在第二次导入时尚未消失，两次相同文案同时在场触发严格模式冲突 | 两次导入之间等待前一个气泡消失 |
